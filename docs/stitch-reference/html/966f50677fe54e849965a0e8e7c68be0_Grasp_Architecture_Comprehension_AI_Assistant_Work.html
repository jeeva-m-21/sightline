Why this exists

We separate mutable order state from immutable financial records to ensure auditability, prevent retroactive changes and maintain a clear boundary between operational data and financial data.

Order (mutable)
  • • Can change
  • • Operational state
  • • Fast access
PaymentLedger (immutable)
  • • Never modified
  • • Financial history
  • • Auditable

Why this exists

The Order entity represents a customer order in the system. It acts as the operational record for a purchase and links to the immutable PaymentLedger for financial transactions.
